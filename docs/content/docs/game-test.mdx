## 🧭 概要

ゲーム内テストでは、実際の Paper サーバーと、1人以上のプレイヤーのバニラ Minecraft クライアントを起動します。クライアントは JSON で書いたシナリオどおりに操作され、スタンプの見た目をスクリーンショットとして保存します。
GitHub Actions ではプルリクエストごとに実行され、スクリーンショットとログが成果物（artifact）としてアップロードされます。

処理の流れは次のとおりです。

1. Mojang のバージョンマニフェストと Paper の API から、テストするバージョンを決めます。`latest` を指定すると、Paper の最新ビルドが `STABLE` である最新リリースが選ばれます。`1.20-` のように範囲を指定すると、1.20 以降で Paper の `STABLE` ビルドがある全リリースが対象になり、CI ではバージョンごとに matrix のジョブとして実行されます。
2. Gradle の `runGameTestServer` タスクで、MineStamp と ProtocolLib を導入した Paper サーバーを起動します。サーバーはオフラインモードのフラットワールドで、RCON を有効にしています。
3. プレイヤーごとに専用の仮想ディスプレイ（Xvfb）を用意し、PortableMC でバニラクライアントとそのバージョン用の Mojang 公式 Java ランタイムを用意して起動します。プレイヤーは1人ずつ Quick Play でサーバーに参加し、`op` を指定したプレイヤーは参加後に OP になります。Microsoft アカウントは不要です。
4. シナリオの各ステップを順に実行します。各ステップは、サーバー・特定のプレイヤー・共通のいずれかを対象にします。
5. スクリーンショットは `build/game-test/screenshots/<プレイヤー名>/` に、ログは `build/game-test/logs/` に保存されます。

スタンプはパーティクルで描画されるため、描画結果がピクセル単位では毎回一致しません。そのため、基準画像との比較は行っていません。

## 📝 シナリオの書き方

シナリオには、参加するプレイヤー（`players`）と、実行するステップ（`steps`）を書きます。ファイルは `game-test/scenarios/` に置きます。
各ステップの `on` で、アクションの対象を指定します。

- `"on": "server"` の場合は、サーバーに対するアクションです。
- `"on": "<プレイヤー名>"` の場合は、そのプレイヤーのクライアントに対するアクションです。プレイヤーは `players` に書いておく必要があります。
- `on` を書かない場合は、共通のアクションです。

アクションは対象ごとに pydantic のモデルとして定義されており（`game-test/scripts/scenario/`）、`action` の値でどのモデルとして検証するかが決まります。対象に合わないアクション、未知のフィールド、`players` に無いプレイヤー名は、サーバーを起動する前にエラーになります。

`players` の各要素:

| フィールド | 説明 |
| --- | --- |
| `name` | オフラインのプレイヤー名（3〜16文字の英数字と `_`）。`server` は予約されているため使えません。 |
| `op` | 省略可。`true` の場合、参加後に OP になります。 |

サーバーのアクション（`"on": "server"`）:

| アクション | フィールド | 説明 |
| --- | --- | --- |
| `command` | `command` | RCON 経由でコンソールコマンドを実行します。 |
| `wait_for_log` | `pattern`、`timeout`（省略可） | サーバーのログに正規表現が現れるまで待ちます。タイムアウトの既定値は60秒です。 |
| `assert_no_log` | `pattern` | サーバーのログに正規表現が現れていたら失敗にします。 |

プレイヤーのアクション（`"on": "<プレイヤー名>"`）:

| アクション | フィールド | 説明 |
| --- | --- | --- |
| `press_key` | `key` | キーを1回押して離します。`F5`、`t`、`Return` などの X11 の keysym 名で指定します。`Enter` と `Esc` も使えます。 |
| `type_text` | `text` | 文字列をキー入力します。 |
| `chat` | `text` | T でチャット欄を開き、文字列を入力して Enter で送信します。コマンドも送れます。 |
| `wait_for_log` | `pattern`、`timeout`（省略可） | クライアントのログに正規表現が現れるまで待ちます。チャットは `[CHAT]` 付きで記録されます。 |
| `assert_no_log` | `pattern` | クライアントのログに正規表現が現れていたら失敗にします。 |
| `screenshot` | `name` | F2 でスクリーンショットを撮り、`<プレイヤー名>/<name>.png` として保存します。 |

共通のアクション（`on` なし）:

| アクション | フィールド | 説明 |
| --- | --- | --- |
| `wait` | `seconds` | 指定した秒数だけ待ちます。 |

次の例では、Alice が F5 を2回押して正面から見た視点にし、`/st :thinking-face:` を実行します。向かいに立つ Bob からの見え方と合わせて、スクリーンショットを撮ります（一部を省略しています）。

```json
{
  "players": [
    { "name": "Alice", "op": true },
    { "name": "Bob" }
  ],
  "steps": [
    { "on": "server", "action": "command", "command": "tp Alice 0.5 -49 0.5 0 30" },
    { "on": "server", "action": "command", "command": "tp Bob 0.5 -49 8.5 180 -15" },
    { "action": "wait", "seconds": 10 },
    { "on": "Alice", "action": "press_key", "key": "F5" },
    { "on": "Alice", "action": "press_key", "key": "F5" },
    { "on": "Alice", "action": "chat", "text": "/st :thinking-face:" },
    { "action": "wait", "seconds": 1 },
    { "on": "Alice", "action": "screenshot", "name": "stamp-thinking-face" },
    { "on": "Bob", "action": "screenshot", "name": "stamp-thinking-face" }
  ]
}
```

## 🚀 実行方法

Linux で実行します。Java 25、[uv](https://docs.astral.sh/uv/)、`xvfb`、`xdotool` が必要です。仮想ディスプレイはスクリプトが起動するため、`xvfb-run` は不要です。

```sh
uv run --project game-test game-test/scripts/run_game_test.py \
  --scenario game-test/scenarios/stamp-thinking-face.json
```

`--minecraft-version` でバージョン（例: `1.21.11`）を指定できます。既定値は `latest` です。
バージョンの範囲がどのバージョンに展開されるかは、次のコマンドで確認できます。

```sh
uv run --project game-test game-test/scripts/versions.py 1.20-
```

Quick Play での参加と 1.18 以降のワールドの高さを前提にしているため、対象は Minecraft 1.20 以降です。
GitHub Actions では、プルリクエストごとに `1.21.6-` の各バージョンで実行されます。MineStamp は Java 25 のバイトコードでビルドされており、Paper 1.21.4 以前では読み込めない（`Unsupported class file major version 69`）ため、それより古いバージョンは既定の範囲に含めていません。`Game test` ワークフローを手動で実行するときは、バージョンの範囲とシナリオを選べます。

テストを実行すると Minecraft のサーバーとクライアントを起動するため、[Minecraft EULA](https://www.minecraft.net/eula) に同意したことになります。サーバーやクライアントのファイルは成果物としてアップロードしません。
