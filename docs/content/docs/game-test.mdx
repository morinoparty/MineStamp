## 🧭 概要

ゲーム内テストでは、実際の Paper サーバーとバニラの Minecraft クライアントを起動します。クライアントは JSON で書いたシナリオどおりに操作され、スタンプの見た目をスクリーンショットとして保存します。
GitHub Actions ではプルリクエストごとに実行され、スクリーンショットとログが成果物（artifact）としてアップロードされます。

処理の流れは次のとおりです。

1. Mojang のバージョンマニフェストと Paper の API から、テストするバージョンを決めます。`latest` を指定すると、Paper の最新ビルドが `STABLE` である最新リリースが選ばれます。`1.20-` のように範囲を指定すると、1.20 以降で Paper の `STABLE` ビルドがある全リリースが対象になり、CI ではバージョンごとに matrix のジョブとして実行されます。
2. Gradle の `runGameTestServer` タスクで、MineStamp と ProtocolLib を導入した Paper サーバーを起動します。サーバーはオフラインモードのフラットワールドで、RCON を有効にしています。
3. PortableMC で、バニラクライアントとそのバージョン用の Mojang 公式 Java ランタイムを用意して起動し、Quick Play でサーバーに参加させます。Microsoft アカウントは不要です。
4. シナリオの各ステップを順に実行します。キー入力は `xdotool` でクライアントのウィンドウに送ります。
5. スクリーンショットは `build/game-test/screenshots/` に、ログは `build/game-test/logs/` に保存されます。

スタンプはパーティクルで描画されるため、描画結果がピクセル単位では毎回一致しません。そのため、基準画像との比較は行っていません。

## 📝 シナリオの書き方

シナリオは、アクションを並べた JSON 配列です。ファイルは `game-test/scenarios/` に置きます。各アクションは `game-test/scripts/scenario.py` で pydantic のモデルとして定義されており、`action` の値でどのモデルとして検証するかが決まります。

| アクション | フィールド | 説明 |
| --- | --- | --- |
| `press_key` | `key` | キーを1回押して離します。`F5`、`t`、`Return` などの X11 の keysym 名で指定します。`Enter` と `Esc` も使えます。 |
| `type_text` | `text` | 文字列をキー入力します。チャット欄を開いた後などに使います。 |
| `wait` | `seconds` | 指定した秒数だけ待ちます。 |
| `wait_for_log` | `pattern`、`source`（省略可）、`timeout`（省略可） | `client`（既定）または `server` のログに正規表現が現れるまで待ちます。タイムアウトの既定値は60秒です。 |
| `assert_no_log` | `pattern`、`source`（省略可） | ログに正規表現が現れていたら失敗にします。 |
| `server_command` | `command` | RCON 経由でサーバーのコンソールコマンドを実行します。 |
| `screenshot` | `name` | F2 でスクリーンショットを撮り、`<name>.png` として保存します。 |

未知のアクションやフィールドは、サーバーを起動する前にエラーになります。そのため、タイプミスはすぐに見つかります。

次の例は、F5 を2回押して正面から見た視点にし、`/st :thinking-face:` を実行してからスクリーンショットを撮ります（一部を省略しています）。

```json
[
  { "action": "wait_for_log", "pattern": "\\[CHAT\\] MineStampTest joined the game", "timeout": 300 },
  { "action": "server_command", "command": "op MineStampTest" },
  { "action": "press_key", "key": "F5" },
  { "action": "press_key", "key": "F5" },
  { "action": "press_key", "key": "t" },
  { "action": "type_text", "text": "/st :thinking-face:" },
  { "action": "press_key", "key": "Return" },
  { "action": "wait", "seconds": 1 },
  { "action": "screenshot", "name": "stamp-thinking-face" }
]
```

## 🚀 実行方法

Linux（X11）で実行します。Java 25、[uv](https://docs.astral.sh/uv/)、`xvfb`、`xdotool` が必要です。

```sh
xvfb-run -a -s '-screen 0 1280x720x24' \
  uv run --project game-test game-test/scripts/run_game_test.py \
    --scenario game-test/scenarios/stamp-thinking-face.json
```

`--minecraft-version` でバージョン（例: `1.21.11`）を指定できます。既定値は `latest` です。
バージョンの範囲がどのバージョンに展開されるかは、次のコマンドで確認できます。

```sh
uv run --project game-test game-test/scripts/versions.py 1.20-
```

Quick Play での参加と 1.18 以降のワールドの高さを前提にしているため、対象は Minecraft 1.20 以降です。
GitHub Actions では、プルリクエストごとに `1.20-` の各バージョンで実行されます。`Game test` ワークフローを手動で実行するときは、バージョンの範囲とシナリオを選べます。

テストを実行すると Minecraft のサーバーとクライアントを起動するため、[Minecraft EULA](https://www.minecraft.net/eula) に同意したことになります。サーバーやクライアントのファイルは成果物としてアップロードしません。
