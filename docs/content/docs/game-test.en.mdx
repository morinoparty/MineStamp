## 🧭 Overview

MineStamp's in-game tests are JUnit tests written with the Kotlin harness of [fukurou](https://github.com/morinoparty/fukurou). fukurou starts a real Paper server and one vanilla Minecraft client per player, and presses keys, sends commands and takes screenshots as the test code says.
The tests live in `src/gameTest/kotlin` and run in a Gradle test suite named `gameTest`. This suite is not part of `./gradlew build` or `task check`. On GitHub Actions they run for every pull request, and a link to a viewer that collects the results of every version is commented on the PR.

## 🏟️ Server and tests

`StampArena` is a JUnit extension that stands for one server. Alice (an operator) and Bob join it, and before each test it prepares the following.

- The harness reset (time, weather, inventories and the arena) and a 5 second wait (`settle`)
- `arena` — builds two stone pillars and puts Alice and Bob on them, facing each other.
- `front-view` — switches Alice to the front view (F5 twice). The view goes back to first person before the next test.

`StampTest` has the following two tests. The method name is the test id.

1. `stamp-thinking-face` — Alice runs `/st :thinking-face:`.
2. `stamp-sleeping-face` — Alice runs `/st :sleeping-face:`.

Both tests check the log line that shows the server received the command, wait 1.5 seconds, and let Alice and Bob take a screenshot at the same time. At the end, they check that no error appeared in Alice's chat. The stamp cooldown (3 seconds of display + 5 seconds of `waitSecond`) is over after 8.5 seconds: 1.5 seconds from the previous test, 5 seconds after the reset and 2 seconds from `arena`.

When another extension class is added and listed with `@ExtendWith`, each extension starts its own independent server, and each result (`paper-<version>-<label>`) is shown side by side in the viewer.

## 🖥️ Running the tests

The in-game tests need Linux (x86_64) with Xvfb, xdotool, xmodmap and Mesa. They usually run on GitHub Actions. To run them locally, install the following packages and run `task game-test`. To choose a version or other settings, run Gradle directly.

```sh
sudo apt-get install --no-install-recommends -y xvfb xdotool x11-xserver-utils \
  libgl1 libgl1-mesa-dri libglx-mesa0 libegl1 libopenal1 libvulkan1 mesa-vulkan-drivers \
  libxrandr2 libxinerama1 libxcursor1 libxi6
./gradlew gameTest -Pfukurou.acceptEula=true -Pfukurou.minecraftVersion=26.2
```

The results are saved in `build/fukurou/out/paper-<version>-stamp-arena/`. The main properties are the following.

| Property | Meaning |
| --- | --- |
| `fukurou.acceptEula` | Setting it to `true` means accepting the Minecraft EULA (required). |
| `fukurou.minecraftVersion` | The version to start. The default is 26.2. |
| `fukurou.paperChannel` | The least stable channel of Paper builds to use (`stable` / `beta` / `alpha`). The default is `alpha`. |
| `fukurou.plugin.minestamp` | The plugin JAR to test. The default is the `shadowJar` output. |
| `fukurou.outDir` | Where the results are written. The default is `build/fukurou/out`. |
| `gameTest.tags` | Tags of the tests to run (comma separated). |

To run only some tests, use Gradle's `--tests` (for example `--tests '*stamp-thinking-face*'`).

## ⚙️ Workflow

`.github/workflows/game_test.yml` is made of the following jobs.

| Job | Description |
| --- | --- |
| `versions` | Decides the list of versions to test with `morinoparty/fukurou/versions` (the default is `1.21.6-`). |
| `build` | Builds the plugin only once. |
| `test` | For each version, prepares the virtual display and other tools with `morinoparty/fukurou/setup` and runs `./gradlew gameTest`. `StampArena` downloads ProtocolLib from its GitHub release. |
| `deploy` | Builds a viewer of the results of every version and every server with `morinoparty/fukurou/ui`, and uploads it to S3. |
| `preview` | Comments the test counts and a link to the viewer on the PR. |

MineStamp is built as Java 25 bytecode, which Paper 1.21.4 and older cannot load (`Unsupported class file major version 69`), so the default range starts at 1.21.6. When the `Game test` workflow is run by hand, the version range, the ids (method names) of the tests to run, tags and the Paper channel can be chosen.

Running the tests starts a Minecraft server and clients, which means accepting the [Minecraft EULA](https://www.minecraft.net/eula).
